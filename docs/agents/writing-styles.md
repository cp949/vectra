# writing-styles

소스·테스트 주석과 문서를 쓰고 고치는 규칙이다. 규칙의 원형은 https://gist.github.com/cp949/d93aa62f6ceb4b1f5cd613febcb4775a 이다. 새 주석·문서는 처음부터 이 규칙으로 쓴다.

소스 주석의 내용과 형태는 `docs/internal/comment-style.md`가 소유한다. 이 문서는 그 문서에 없는 공통 문장 규칙, 참조 표기, 문서 규칙을 소유한다.

## 적용 대상

| 대상        | 예                                                                      |
| ----------- | ----------------------------------------------------------------------- |
| 소스 주석   | `sub/vectra/src`, `sub/playground/src`, `apps/*/src`, `scripts/*.mjs`   |
| 테스트 주석 | `sub/vectra/tests`, `*.test.ts(x)`, `scripts/*.test.mjs`                |
| 문서        | `docs/**`, `README.md`(루트·`sub/*`·`apps/*`), 그 밖의 `*.md`           |

## 공통 문장 규칙

- 언어: 한국어. 식별자·명령어·에러 메시지는 원문 그대로 둔다.
- 억지로 번역하면 어색한 기술 용어(`clamp`, `aliasing`, `degenerate`, `epsilon`)는 영어 그대로 쓴다.
- 종결: `~한다`체. 명사구 종결은 목록 항목과 표 셀에서 허용한다.
- 한 문장에 한 사실만 담는다.
- 이유·결과·예외를 `—`, `~하므로`, `~해서`로 이어 붙인 긴 문장은 나눈다.
- 나열·순서·조건 분기는 산문 대신 목록으로 쓴다.
- 표 셀도 한 문장으로 쓴다.
- 확인한 사실만 쓴다. 코드를 읽지 않고 설명하지 않는다.
- 사실에 맞아도 어색한 표현은 자연스러운 한국어로 고친다. 번역투·직역투·부자연스러운 조사와 어순이 대상이다.

나눔 예:

```text
전: bounds는 min과 max를 정규화해서 기록하는데 inverted 입력도 받고 out은 입력과 같은 object여도 된다.
후: bounds는 min과 max를 정규화해 기록한다.
    inverted 입력도 받는다.
    out은 입력과 같은 object여도 안전하다.
```

목록 분해 예:

```text
전: 규칙: 교차가 없으면 false를 반환하고, 이때 out은 수정하지 않으며, 접점 하나는 교차로 본다.
후: 규칙:
    - 교차가 없으면 false를 반환한다.
    - false일 때 out을 수정하지 않는다.
    - 접점 하나는 교차로 본다.
```

## 소스 주석

- 무엇을 쓰고 어떤 형태로 쓰는지는 `docs/internal/comment-style.md`를 따른다.
- 위 "공통 문장 규칙"은 소스 주석에도 적용한다.
- companion과 `*Into`의 책임 메모는 같은 카테고리 문구를 양쪽에 둔다. `pnpm jsdoc:companion:check`가 대칭을 검사한다.
- 코드가 말하는 것은 쓰지 않는다. 이름을 되풀이하는 주석은 지운다.

## 테스트 주석

- 테스트 제목 규칙은 `docs/internal/testing-mechanics.md`를 따른다.
- 파일 머리 블록: 무엇을 테스트하나, 규칙이 사는 문서 위치. 필요할 때만 둔다.
- `describe` 묶음 앞 `//` 블록: 그 묶음이 고정하는 결함이나 계약. 이름만으로 드러나면 생략한다.
- 이름 있는 헬퍼 함수: TSDoc 한 개. 테스트 본문 안 지역 헬퍼는 `//`.
- 기존 테스트 제목은 일괄 변경하지 않는다. 그 테스트를 고치는 시점에 바꾼다.
- 주석만 고치는 커밋에서는 제목을 바꾸지 않는다.
  - 예외: 제목이 존재하지 않는 대상을 가리키면 고친다.
- 상수를 일부러 import하지 않고 리터럴로 두면 그 이유를 쓴다(값이 바뀌면 테스트가 실패하게 한다).

## 참조 표기

허용:

| 표기                                | 뜻                                       |
| ----------------------------------- | ---------------------------------------- |
| `docs/internal/*.md`와 절 제목      | 규칙이 사는 절                           |
| `ADR NNNN`                          | 이 저장소 `docs/internal/adr/`의 결정    |
| `docs/agents/*.md`                  | 이 저장소의 작업 규칙 문서               |
| `docs/guides/*.md`, `docs/reference/*.md` | 사용자 대상 계약과 사용법          |

금지. 저장소에 남지 않거나 작업 문맥에 묶인 곳을 가리키기 때문이다.

| 표기                                         | 대신                                          |
| -------------------------------------------- | --------------------------------------------- |
| `DELTA-NN`, `RD-NN`                          | 지운다. 남길 내용이 있으면 결과만 쓴다        |
| `_works/…` 경로                              | 지운다. 작업 폴더는 저장소에 남지 않는다      |
| `_tmp/…` 경로                                | 지운다. 임시 폴더는 Git 추적 대상이 아니다    |
| `docs/superpowers/…`, `.superpowers/…` 경로  | 지운다. 저장소 계약이 아닌 도구 전용 계획이다 |
| `.scratch/…` 경로                            | 지운다. 남길 근거는 문장 안에 쓴다            |
| `src/` 주석의 정책·roadmap ID                | 실행 계약으로 풀어 쓴다                       |
| 없는 파일                                    | 지운다. 근거는 문장 안에 쓴다                 |

- `src/` 주석의 ID 금지는 `docs/internal/comment-style.md`의 "금지 또는 정리 대상"을 따른다.
- 참조 문서·경로는 존재를 확인한 뒤 쓴다. 절 제목이 바뀌면 참조도 같이 고친다.
- "계획서에 따르면" 같은 소멸한 문서 인용은 근거 문장으로 바꾼다.

## 문서

문서 위치는 아래와 같다. 빈 폴더나 빈 문서를 미리 만들지 않는다.

| 위치                         | 담는 것                                                  |
| ---------------------------- | -------------------------------------------------------- |
| `docs/guides/`               | 사용자 대상 사용법                                       |
| `docs/reference/`            | 사용자 대상 참조 표                                      |
| `docs/internal/`             | 설계·정책·운영의 현재 계약. 색인은 `docs/internal/README.md` |
| `docs/internal/adr/`         | 방향. 되돌리기 비싼 큰 결정과 대안. 결정 근거의 원천     |
| `docs/internal/agent-traps/` | 에이전트가 반복한 실수와 방지 방법                       |
| `docs/internal/checklists/`  | 작업 완료·release 점검 기준                              |
| `docs/agents/`               | 에이전트 작업 규칙                                       |
| `README.md`                  | 구성과 실행 방법                                         |

`docs/internal/`은 현재 시점의 규칙·계약·근거만 담는다. 작업 이력·측정 로그·이전 구현의 기록이 아니다. 다른 문서도 같은 원칙을 따른다.

### 쓰는 것

- 규칙·계약·불변식.
- 그 규칙이 있는 이유. 한 항목에 이유 하나.
- 실행 방법은 복사해 실행할 수 있는 명령으로 쓴다.
- 실측 근거는 사실 한 문장. 측정 환경(버전·조건)을 함께 쓴다.
- 추정은 추정이라고 밝힌다. 확인하지 않은 것은 확인하지 않았다고 쓴다.

### 쓰지 않는 것

| 쓰지 않는 것                                              | 대신                                        |
| --------------------------------------------------------- | ------------------------------------------- |
| 소스 줄 번호·줄 수                                        | 파일·함수 이름                              |
| 파일·테스트·패키지·항목 개수                              | 이름 목록. 목록이 이미 있으면 개수를 지운다 |
| 실행 결과 로그·ms 분포·표본 수                            | 실측 사실 한 문장                           |
| 이전 구현·옛 구조·"수정 전 코드" 서술                     | 현재 동작                                   |
| "~를 더했다"·"~로 모았다" 같은 작업 이력                  | 현재 동작                                   |
| 날짜와 "사용자 확정·결정" 귀속                            | 지운다                                      |
| `DELTA-NN`·`_works/`·`_tmp/` 경로·없는 문서 인용          | 지운다. 남길 내용은 근거 문장으로 쓴다      |

예외: 규칙 자체가 수치인 값은 쓴다(epsilon, 상한). 값의 원천은 상수 이름으로 가리킨다.

### 규칙의 위치

- 규칙·상수는 한 곳에만 쓴다. 다른 곳은 문서 위치로 링크한다.
- 같은 규칙을 두 문서에 다시 쓰지 않는다. 겹치는 곳을 찾으면 한쪽을 링크로 바꾼다.
- 새 절은 문서 끝에 붙인다. 다른 문서·소스·테스트가 제목으로 참조하는 절은 제목을 유지한다.
- 절 제목을 바꾸거나 절을 지우면 저장소 전체 참조를 검색해 같이 고친다.
- `docs/internal/`에 문서를 추가하면 `docs/internal/README.md` 색인 표에 한 줄을 추가한다.
- ADR은 결정과 근거를 자체로 완결되게 쓴다. 병합 뒤 사라지는 작업 문서에 의지하지 않는다.

### 수명

`docs/internal/adr/`와 `docs/internal/`의 설계 문서는 현재 시점의 내용만 쓴다. 과거 이력을 누적하지 않는다. 이력은 Git 이력이 소유한다.

- 결정이 바뀌면 문서를 현재 결정으로 고쳐 쓴다. 이전 결정을 아래에 덧붙이지 않는다.
- ADR이 기각한 대안은 현재 결정을 이해하는 데 필요한 이유만 쓴다.
- 무효가 된 문서는 삭제한다.
- 다른 문서·소스·테스트가 참조하는 문서는 바로 지우지 않는다. `상태:` 줄을 `상태: 무효`로 바꾸고 대체 문서를 적는다. 대체가 없으면 `대체 없음`을 적는다.
- 무효 표시한 문서를 새로 참조하지 않는다.
- 참조를 모두 제거한 뒤 문서를 삭제하고 `docs/internal/README.md` 색인의 항목도 지운다.
- 참조 검색: `grep -rn "<파일 이름 또는 ADR NNNN>" sub apps scripts docs README.md --exclude-dir=node_modules --exclude-dir=dist`

### 형태

- 이유 문장 하나에 결정·근거·기각안을 이어 붙이지 않는다. 목록 항목 하나에 사실 하나씩 쓴다.
- 진행 순서·번호가 있는 절차는 번호 목록을 쓰고, 항목 안 부연은 하위 목록으로 내린다.
- 표 셀은 문장 단위로 끊는다.
- 수치는 실측 값을 쓴다. 추정치를 쓰면 추정이라고 밝힌다.
- 테스트 제목을 인용하면 실제 제목과 대조한다.

## 고칠 때

1. 주석을 다시 쓰기 전에 대상 코드를 읽는다. 설명이 코드와 다르면 코드에 맞춰 고친다.
2. 틀린 설명을 찾으면 문체만 바꾸지 않고 내용을 바로잡는다. 커밋 메시지에 밝힌다.
3. 고친 수치는 다시 센다.
4. 문체만 바꾸는 커밋에서는 코드 동작을 바꾸지 않는다. 이름·로직 변경은 별도 커밋으로 분리한다.
5. 주석만 고치는 커밋에서는 테스트 제목을 그대로 둔다. 존재하지 않는 대상을 가리키는 제목만 고친다.
6. 이미 구현된 영어 주석·테스트 제목은 한국어로 바꾸기 위한 일괄 변경을 하지 않는다. 그 주석이나 테스트를 고치는 시점에 한국어로 바꾼다.
7. 기존 위반(금지 표기 등)도 같은 방식으로 다룬다. 그 파일을 고칠 때 함께 고치고, 위반 정리만을 위한 일괄 변경은 하지 않는다.

## 검증

- 금지 표기 잔존 검사(이번에 고친 파일이 출력에 없어야 한다). 작업 폴더를 설명하는 워크플로 문서·템플릿과 기존 운영 문서의 정당한 언급은 제외 대상이다:
  `grep -rnE "DELTA-[0-9]|_works/|_tmp/|\.scratch/|docs/superpowers" sub apps docs README.md --include=*.ts --include=*.tsx --include=*.md --exclude-dir=node_modules --exclude-dir=dist --exclude-dir=templates --exclude=writing-styles.md --exclude=workflow-shared.md --exclude=qq-workflow.md --exclude=roadmap-workflow.md`
- 소스 주석을 고쳤으면 `pnpm jsdoc:companion:check`를 실행한다.
- 마크다운은 formatter 검사 대상이 아니다. `git diff --check`로 공백 오류를 확인한다.
