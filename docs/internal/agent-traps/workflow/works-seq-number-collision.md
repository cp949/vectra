# `_works` 다음 seq 번호 선정 시 잘림·비수치 정렬로 충돌

태그: `planning`, `_works`, `seq`, `directory-listing`

## 함정

새 `_works/<로드맵ID>/<yyyyMMdd>-<seq>-...` 폴더의 다음 `<seq>`를 정할 때 `ls | tail` 출력만
보고 번호를 고르는 실수. 두 가지 이유로 기존 seq와 충돌한다.

1. seq가 두 자리를 넘어 100+가 되면 `ls`의 기본 사전(lexical) 정렬이 수치 정렬과 어긋난다
   (`20260525-100` < `20260525-99` 가 아님). `tail -20`이 99에서 끊겨 100~103을 못 본다.
2. 같은 날짜에 여러 작업이 쌓이면 최신 seq가 목록 끝이 아니라 중간에 있을 수 있다.

```sh
# 함정: tail이 99에서 잘려 이미 존재하는 100~103을 못 봄 → seq 100 재사용
ls -1 _works/S1-RM-013/ | tail -20
```

## 증상

- 새 계획 폴더를 `20260525-100-...`로 만들었는데 `20260525-100-...`가 이미 존재해 같은 seq가 둘.
- 충돌을 뒤늦게 발견해 폴더를 rename해야 한다.

## 방지

다음 seq는 항상 seq 숫자로만 정렬한 마지막 값에서 +1 한다.

```sh
ls -1 _works/<로드맵ID>/ | grep -oE '^[0-9]{8}-[0-9]+' | sort -t- -k2 -n | tail -3
```

과거 상태 대시보드의 "최근 완료 작업"에 적힌 최신 seq도 교차 확인한다(`tail` 목록보다
신뢰도 높음). 두 출처가 어긋나면 더 큰 값을 따른다.

## 관련 작업

- `_works/S1-RM-013/20260525-104-ray-segment-hit-example/` (seq 100 충돌 → 104로 정정)
- `_works/S1-RM-013/20260525-110-vec-surface-normal-example/` (seq 100 재충돌 → 110으로 정정,
  상태 대시보드 최신 seq 109 교차 확인 누락이 원인)
