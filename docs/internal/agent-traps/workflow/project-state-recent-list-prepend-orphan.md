# 상태 대시보드 "최근 완료 작업" 맨 앞 추가 시 직전 top 항목 헤더 덮어쓰기

태그: `planning`, `state-dashboard`, `recent-completed`, `edit`

## 함정

과거 상태 대시보드의 "최근 완료 작업"은 최신 항목을 맨 위에 prepend하고 최대 2개만 유지한다.
새 항목은 2~3줄 요약으로 작성한다.
새 항목을 추가할 때 Edit `old_string`에 섹션 헤더 + **직전 top 항목의 헤더 줄**을 함께 잡고,
`new_string`에는 새 항목만 넣고 직전 top 헤더를 다시 적지 않으면, 직전 항목의 헤더 줄이 사라진다.

각 항목은 `- ...완료` 헤더 1줄 + 들여쓴 `  - 변경:` / `  - 검증:` detail 줄들로 구성되므로, 헤더만
사라지면 직전 항목의 detail 줄들이 **새 항목 헤더 아래로 orphan**된다(한 헤더에 두 항목의 변경/검증이
섞임).

```md
<!-- 함정: old_string에 직전 top 헤더를 포함했는데 new_string에서 복원하지 않음 -->
## 최근 완료 작업

- `...145-rect-cover-fit...` 완료
  - 변경: ...(신규)
  - 변경: ...(144 star-polygon detail이 145 헤더 아래로 orphan)
  - 검증: ...(144 검증)
```

## 증상

- 새 항목 아래에 이전 항목의 `- 변경:`/`- 검증:` 줄이 따라붙어 한 헤더에 detail이 2벌.
- "최대 2개 유지" 카운트가 헤더 기준으로는 줄어든 것처럼 보이지만 detail은 그대로 남는다.

## 방지

- prepend는 섹션 헤더만 anchor로 잡는다. `old_string`을 `## 최근 완료 작업\n` 까지만 잡고
  `new_string`에 `## 최근 완료 작업\n\n- <새 항목>\n  - 변경: ...\n  - 검증: ...` 를 넣으면
  직전 항목 헤더를 건드리지 않는다.
- 부득이 직전 top 헤더를 `old_string`에 포함했다면 `new_string`에 그 헤더 줄을 **그대로 다시
  포함**한다(새 항목 → 직전 헤더 순).
- 새 항목에는 `- 변경:`과 `- 검증:` 두 detail 줄을 같이 적는다. 직전 항목 detail이 자기 헤더를
  잃지 않았는지 추가 후 해당 구간을 다시 읽어 확인한다.
- 2개 초과 시 가장 오래된 항목은 헤더 + 그 detail 줄 전체를 함께 제거한다(헤더만 지워 detail orphan
  금지).
