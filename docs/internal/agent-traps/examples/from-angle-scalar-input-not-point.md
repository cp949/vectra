# 각도 → 벡터 구성 예제는 입력이 점이면 두 점 함수로 붕괴한다

태그: `examples`, `pixi-demo`, `ux`, `vec`

## 함정

`vec/fromAngle`(각 → 단위 방향), `angle`/`heading` 역방향, polar 구성처럼 **스칼라 각을 입력으로
받는** 함수의 예제를 만들 때, 각을 2D 드래그 핸들에서 `atan2(handle − center)`로 뽑아 넣으면 예제가
수학적으로 두 점 함수와 동치가 되어 시연 대상 함수의 고유 가치가 사라진다.

```txt
θ = atan2(handle.y − center.y, handle.x − center.x)
dir = fromAngle(θ)
// ⇒ dir === directionTo(center, handle)  (fromAngle이 하는 일이 보이지 않는다)
```

화면에는 핸들을 돌리면 단위 벡터가 회전하는 그럴듯한 장면이 나오지만, 그 장면은
`vec-aim-direction`(`directionTo`)이 이미 보여주는 것과 같다. `fromAngle`이 "점 없이 순수 각도값에서
방향을 만든다"는 고유 개념은 화면 어디에도 드러나지 않는다.

## 증상

- 예제의 입력이 자유 2D 핸들이고, 각을 그 핸들에서 `atan2`로 계산한다.
- 시연 함수를 `directionTo`/`angleTo`/두 점 기반 함수로 바꿔도 화면이 똑같다.
- "기존 두 점 방향 예제(`vec-aim-direction`)와 무엇이 다른가"에 "함수 이름이 다르다" 외에 답을 못 한다.
- diagnostics의 angle 값이 입력이 아니라 핸들 위치에서 파생된 결과다.

## 방지

각을 받는 함수의 예제는 **입력 각이 점이 아닌 스칼라**가 되도록 입력 위젯을 고른다.

- 1-DOF 슬라이더(수평/수직 트랙 위치 → θ), 다이얼 값, 애니메이션 위상 등 점 쌍이 개입하지 않는 입력.
- 슬라이더 위치 `p ∈ [0,1]` → `θ = p · 2π`처럼 스칼라 → 스칼라 매핑으로 각을 만든 뒤 함수에 넘긴다.
- 출력(단위 벡터)은 단위원 위 arrow로 그려 "스칼라 각 → 2D 방향"이라는 정보 증가를 보인다.

이렇게 하면 입력에 방향 정보가 없으므로 두 점 함수로 대체할 수 없고, 시연 함수의 고유 역할이 화면에
강제로 드러난다.

- 시연 함수를 두 점 함수(`directionTo` 등)로 바꿨을 때 화면이 달라지는지 확인한다. 안 달라지면 입력
  설계를 다시 한다.
